# Planning a reward ladder before writing the code

**Public page:** `/reward-ladder-plan` on a deployed version of this portfolio.

A worked plan for adding tiered reward progress to a cart that a third-party app owns. The shop, offer, amounts, and gift names are **fictional**, and the plan is independently written. It is not the proposal, configuration, or source of any employer project.

## What the plan covers

1. **The decision:** build on a controlled copy, then QA what the cart promises against what the automation grants, before any release.
2. **What the audit found:** who owns the visible cart, why three markers can sit on two qualification systems, how labels that already say "Free" break sentence frames, and why offer values must never be hardcoded.
3. **The data contract:** one configuration entry, validated strictly, with no fallback values.
4. **What the customer sees:** example messages generated by the same engine as the demo, so the plan cannot drift from the code.
5. **Failure behaviour:** closed on data, open on structure.
6. **The build plan:** six phases, each with a gate.
7. **Risks and mitigations.**
8. **Acceptance criteria.**
9. **Measuring the effect:** baselines, order bands, net of the reward cost, and confounders. No uplift is claimed.
